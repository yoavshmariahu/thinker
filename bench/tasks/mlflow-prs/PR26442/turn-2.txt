Endpoints in the AI Gateway that use the TypeSafe provider always send requests to TypeSafe's public hosted service address. Users who need to go through a proxy or run their own self-hosted System One server have no way to point the endpoint at a different address, so those setups can't be used. The endpoint form also doesn't offer an optional API Base URL field for saved TypeSafe connections, so there is nowhere to enter a custom address.

Desired behavior: a TypeSafe endpoint can be configured with an optional custom API base URL. When one is set, all requests the Gateway forwards to TypeSafe go to that address instead of the public one. When it is left empty, the public hosted address remains the default, so existing endpoints behave exactly as before. For saved TypeSafe connections, the endpoint form should show the optional API Base URL field, and a value saved there must carry through when the Gateway builds the provider for the endpoint. The provider's listed configuration options should also show the base URL as an optional setting. The documentation for model providers should describe this option and when to use it, such as with a proxy or a self-hosted server.

Details the tests check:
In the provider catalog, TypeSafe's API-key auth mode lists exactly one optional config field: name `api_base`, type `string`, description "TypeSafe API Base URL (defaults to https://api.typesafe.ai/v1)", not required.
