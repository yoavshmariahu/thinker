The session bill uses 20 calls at 10¢ each, holding the cost mix and 200k cached tokens fixed to show how costs add up. The repeated-cost counter isolates that original context at 4¢ per call; the growing bars illustrate additional context accumulating, whose cost is not included in the counter. These are illustrations, not a measured session. The compression example starts with 200k cached tokens, removes 120k net of placeholders, and assumes 40k retained tokens need rewriting. Each call adds the same $0.060 of fresh input, new writes, and output in both cases. The example isolates this context’s lifetime: it assumes a warm cache, no further cuts, no extra rereads, and identical work. Actual write size depends on reusable cache boundaries; recovery depends on later calls. Instruction and knowledge examples are separate illustrations and are not added to compression savings. Trimming 8k instruction tokens avoids 160k context-read tokens over 20 later calls in the same session; dollar savings depend on fresh input, writes, and reads. The knowledge example replaces 40k exploration tokens with a 2k note pack: 38k less context carried into each later call. Over 20 later calls in the same session, that avoids 760k context-read tokens. Both examples assume the removed context would otherwise remain in every later request, with no intervening compression. The knowledge example assumes the notes answer the same questions without extra exploration. Figures exclude the initial exploration difference and learning or verification costs; they are illustrative read-token reductions, not measured outcomes or net dollar savings.

The final runway visual is conceptual: reducing repeated context can leave more of a token budget available for useful work. It does not specify an increase in tasks, subscription allowance, or session length. Rewrites, learning and verification also consume tokens; actual results depend on the workload and agent.
