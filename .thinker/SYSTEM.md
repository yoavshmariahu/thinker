# Desired behaviors of thinker

Rules the code must uphold, kept as `behavior` notes in `.thinker/notes/` and checked by `thinker verify`. A **fixed** behavior is never revised; a **mutable** one is revised only by a change that edits its note. Generated by `thinker system md`; edit the notes, not this file.

## Fixed

### Verification never retires a desired behavior, and rewrites one only to match merged code

*fixed; id `verification-never-rewrites-or-retires-a-desired-behavior`; **unverified***

A `behavior` note is a rule a person wrote. When its deps change, src/ops.js:verifyNote hands it to src/ops.js:verifyBehavior, whose verdicts are `holds` (re-baseline), `moved` (deps re-pointed, history kept), and for code that no longer upholds it either `broken` or `revised`, decided by src/ops.js:onDefaultBranch: code that is not merged (a working tree, a branch, unpushed commits) leaves the text alone and sets status `violated` with the commit and reason; code merged on the default branch is the truth, and the behavior's body is replaced with what the code upholds now, the old body kept in `history` and `revised` recording the commit and reason. No path sets a behavior to `invalid`, lowers its confidence, or rewrites it for unmerged code; the ordinary verdicts `update` and `invalid` never reach a behavior.

Upheld at: `src/ops.js:verifyNote`, `src/ops.js:verifyBehavior`, `src/ops.js:onDefaultBranch`

### A review never writes to the cache

*fixed; id `a-review-never-writes-to-the-cache`; revised 2026-10-13 to match commit 68acdf2ebf*

A review never writes to the knowledge cache: `thinker review` and the MCP `review` tool must not create, rewrite, re-hash, retire or mark stale any note, whatever the verdict.
Review may write only usage and impact records, and task verification may persist evidence under `.thinker/local/reviews/` (local task context, frozen inputs, execution evidence, human reports, local Git snapshot refs); these never rewrite the notes used to assess a candidate.
An outdated or already-stale note is reported with the `thinker verify` command that re-checks it.
Current state: src/review.js (review, assessNote, assessBehavior, assessHolistic) has been removed, so no code in the repository shown here enforces this guarantee.
The only write path shown is src/store.js:log, which appends one usage event per line to a machine log file and does not touch notes.

Upheld at: `src/store.js:log`

### Serving and assessment never rewrite a shared note's committed file

*fixed; id `serving-and-assessment-never-rewrite-a-shared-note-s-committ`*

Files under `.thinker/notes/` change only through an explicit `thinker share` (src/store.js:Store.promote), a sync pull, or a person editing them. Everything a checkout learns about a shared note (uses, servedIn, attest, status, staleness, a pending correction) goes to the overlay under `.thinker/local/shared/`: src/store.js:Store.put writes the overlay and leaves the committed file as it is whenever `isShared(id)`. So orienting, lookups, the end-of-session assessment (src/ops.js:attest) and background verification can run on every checkout without producing a dirty working tree or a merge conflict in the notes.

Upheld at: `src/store.js:Store.put`, `src/store.js:Store.promote`, `src/ops.js:attest`

### THINKER_TELEMETRY=off and test runs send no telemetry

*fixed; id `thinker-telemetry-off-and-test-runs-send-no-telemetry`*

src/telemetry.js:isTelemetryEnabled returns false before any other check when `THINKER_TELEMETRY` is `off`, `0` or `false`, when `THINKER_NO_TELEMETRY=1`, or when `THINKER_NO_LEARN=1`; a test run (`THINKER_TEST=1`, or Node's own test context) never reaches the production endpoint. Every send goes through this gate, so tests, benchmarks, evaluation harnesses and CI reviews that set the variable are not counted as installs or usage. The order matters: the environment switch must win over any repository config or scheduled job that would turn telemetry on.

Upheld at: `src/telemetry.js:isTelemetryEnabled`

*mutable; id `a-fixed-desired-behavior-blocks-the-change-when-code-stops-u`; **unverified***
