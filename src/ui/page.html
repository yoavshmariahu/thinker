Where is my data stored? Does anything leave my machine?

Everything Thinker learns stays on your machine. The profile of how you work in a repository is under its .thinker/local/, which git ignores; there is no team sharing or sync. .thinker/config.json holds the configuration. Per machine, ~/.thinker/ holds the installed app, the usage log, the savings ledger and the proxy's records.

Three things leave the machine, and nothing else:

  • Model calls go to the provider you already use for your agent. Reading a session into the profile runs through your agent's own login (claude, or an Anthropic API key), or, in a desktop app (Claude Desktop, the Codex app, Cursor), through the app's own session. A session is read from its prompts and the agent's answers alone, never its tool calls or their results.
  • Telemetry is counts only. An hourly report carries numbers: requests, sessions, what the clearing saved, the profile's two arms, token totals, with an install id and a hashed device id. It contains no code, profile text, prompt text, file paths or repository URLs. THINKER_TELEMETRY=off or { "telemetry": false } in the config stops it.
  • The ranking model is downloaded once at install (about 23 MB) and runs on your machine.

This page listens on 127.0.0.1 only.

A repository with sensitive content can be turned off with thinker disable inside it. Thinker then does nothing there, in any clone or worktree: the hooks and the MCP server serve nothing, no session is read, and nothing is written into it. thinker enable turns it back on.

What does Thinker do in a session?

Two things. It clears what the agent has finished with out of its context: older tool results are replaced in the requests the agent sends, so every later call reads a shorter prompt. That is where the cost is, and it is measured, not estimated. And it puts a profile of how you work in this repository into the session's first prompt: what you are in the middle of, how you want work done and answers given, what went wrong before and the recent bugs. The profile goes in again after a compaction, since a compaction summary keeps none of it.

  • The profile is learned from your sessions, when they end: a model reads the prompts and the agent's answers, records what was asked and how you reacted, and patches the profile with it. About 1,500 tokens a session start, cached.
  • The spend is bounded. One model call per session, through your agent's login, and learning stops at a daily token cap (maintain.dailyTokens in .thinker/config.json).
  • You can stop it. { "learn": { "profile": false } } in the config stops the profile in a repository; THINKER_NO_LEARN=1 stops all learning. thinker profile show prints what a session is shown, --why the evidence behind each line.

Can Thinker cut what my agents load into every session?

It shows you what to cut, and you decide. The Find Savings view here and thinker context list every section of your instruction files, every skill and every tool with what it costs a prompt and how many sessions it bore on. A section you pick can be removed or compressed by a model: Apply starts it in the background and opens a pull request with the change, which Recent activity follows.

How can I tell if Thinker is helping my agents?

  • The savings are measured. The status line, the cards and thinker savings say what the clearing saved today and over the whole log, at list prices; View Report here shows it week by week beside what a session costs.
  • The Find Savings view here, and thinker context, show where your agents' context goes: what each instruction section, skill and tool costs a prompt and how often sessions acted on it, so what you cut is measured on your own sessions.
  • The profile has a holdout. 15% of sessions see no profile, chosen by a hash of the session id, and every observation learned from a session carries which side it was on. thinker profile holdout compares corrections and redirects per session on each side; fewer than twenty sessions a side is too few to read.
