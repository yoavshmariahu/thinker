System behaviors
The rules every change must keep

A behavior says what your system must always (or never) do, and where the code upholds it. An agent editing the code a behavior rests on is handed it first. They come from the design documents checked into the repository and are yours to edit or discard. A mutable behavior is revised when merged code changes it; a fixed one never is. Proposed behaviors are not requirements until you accept them.

Where is my data stored? Does anything leave my machine?

The cache lives in the repository it describes and stays on your machine: notes, from pull requests and sessions alike, under .thinker/local/, which git ignores (notes an older version committed under .thinker/notes/ are still read); the configuration in .thinker/config.json. There is no team sharing or sync. Per machine, ~/.thinker/ holds the installed app, the usage log this page reads, and the ranking model.

Three things leave the machine, and nothing else:

  • Model calls go to the provider you already use for your agent, through its own login (claude, codex, gemini, cursor, or an Anthropic API key): a condensed transcript when a session is distilled, a pull request's title, description, review comments and diff when it is mined, a note with the diff of its code when it is re-verified. Thinker runs no model and stores nothing of its own in the cloud.
  • Telemetry is counts only: an hourly report of notes served, verdicts, token totals and the holdout sums, with an install id and a hashed device id. No code, note bodies, prompt text, file paths or repository URLs. THINKER_TELEMETRY=off or { "telemetry": false } in the config stops it.
  • The ranking model is downloaded once at install (about 23 MB) and runs on your machine.

gh reads merged pull requests from GitHub during mining and posts nothing. This page listens on 127.0.0.1 only.

A repository with sensitive content can be turned off on the warm-up page, or with thinker disable inside it. Thinker then does nothing there, in any clone or worktree: the hooks and the MCP server serve nothing, no session is distilled, no pull request is read, and nothing is written into it.

How does the cache work? What does it do to make my agents faster?

A note is a short rule, map or how-to about one part of the code, with file:Symbol pointers and a hash of the code it rests on. The work is in putting the right one in front of the agent without being asked:

  • On each request a hook picks the lexical candidates, then a local ranking model reads the request against them and serves up to two notes, only those it scores relevant, with the code behind their pointers. The agent starts at the code instead of searching for it.
  • On each file edit the rules resting on that file are served, so a trap on that code is in view while it is changed.
  • On demand, the MCP tools orient and lookup give the agent notes when the hooks served nothing.
  • Never stale. Every serving re-hashes the dependencies of every note against your working tree. A note whose code changed is held back, re-verified in the background, and served again once it is fresh.
  • Once per session, not for one-word turns, and not at all when nothing fits.

The cache grows from your sessions: each is distilled once when it ends, and a maintenance run every four hours re-verifies a few stale notes, phrases the new ones and archives the ones sessions never acted on. Newly merged pull requests are not mined in the background unless maintain: { prs: true } is set in .thinker/config.json; thinker mine-prs reads them by hand.

Why does mining take so long? Can I skip it?

Each merged pull request is read by a frontier model through your agent's login: title, description, review comments and the diff, about 14k tokens and 8 seconds per pull request, four at a time. The default build reads up to 60 of them, then reads the design documents and writes search phrasings for every new note, each a model call. Rate limits on the login stretch it further. The estimate in tokens and minutes is shown before anything is spent.

Yes, you can skip it, and nothing stops working:

  • Press Skip for now on the warm-up view, or run thinker setup --no-build. Thinker is wired and the cache grows from your own sessions.
  • Pick Shallow: the newest 30% of the same pull requests.
  • Stopping a build at any point keeps every note saved so far. thinker mine-prs continues where it stopped, 20 pull requests at a time, and the background maintenance mines a few new ones per run anyway.

What a build gives you that sessions cannot is the record of past fixes. A repository with little history loses little by skipping it.

How can I tell if Thinker is helping my agents?

  • At the end of each turn one line says what was served and the code it pointed at. It does not say "saved": whether the agent acted on a note is known only once the session is assessed.
  • The Context view here, and thinker context, show where your agents' context goes: what each instruction section, skill and tool costs a session and how often sessions acted on it, so what you cut is measured on your own sessions.
  • The usage under Cache here, and thinker usage, show notes served, what the sessions did with them (confirmed, contradicted, unused), what learning and maintenance cost in tokens, and an estimate of the reads avoided.
  • The holdout is measured, not estimated. 15% of prompts are served nothing, chosen by a hash of the session and the turn, and what every turn cost is read from the session's transcript. Once twenty prompts stand on each side, the holdout section compares the cost per prompt: tool calls and tokens with notes against without, on your repository, by your agent.
  • thinker benchmark pr runs a recent merged pull request with and without the cache and compares time, turns, tool calls and tokens; both answers are saved under .thinker/benchmarks/ so you can judge their quality.

A note served is not a note used. Read the confirmed and unused counts rather than the hit rate; a cache that serves often and is rarely acted on is costing tokens, and maintenance archives such notes over time.
