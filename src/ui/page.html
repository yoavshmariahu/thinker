System behaviors

The rules every change must keep

A behavior says what your system must always (or never) do, and where the code upholds it. thinker review warns about a change that breaks one, and stops the change when the behavior is blocking. Proposed behaviors (build drafts and agent proposals) are not requirements until you accept them.

Define them with your coding agent

The best way to write behaviors down is a conversation: your agent asks you how each part of the system must behave, drafts each rule against the code, and saves only the ones you approve.
