# Performance canary on the latest Thinker revision

Authors: Codex and Yoav. Frozen before model calls, 2026-10-06.

Three real Click changes (#3364, #3391, #3677), the same tasks for Opus 5.5 (`claude-opus-5-5`), GPT-6.1 Sol (`gpt-6.1-sol`) and Gemini 3.8 Flash (`gemini-3.8-flash-high`), all high effort. Three tasks × three models × baseline/Thinker = 18 coding runs. No automatic expansion: inspect this canary first. Pin Thinker at current main when this experiment starts, including the recent Jev learning changes; execution.json records the exact revision and task hash. No provider/model fallback and no outcome-driven retries.

Each task/model gets a fresh exploration session on only pre-change code, then a separate distillation of that session. Both use the coding cohort's exact model/effort; no old caches, target request, gold patch or future tests are shown to exploration. Exploration receives a topic-level request and returns proposed reusable notes as part of its transcript. The final setup follows parseTranscript → refineLearningPlan → distillEvents → prepareNotes → saveNotes. Jev 1.13.0 selects and checks evidence using the existing explicit live-test transport and a personal key directly to TypeSafe. All processes retain THINKER_TEST=1: no production telemetry, hosted registration or background learning. Jev responses and failures are retained; unavailable inference is not replaced silently. This is an explicit session-learning simulation, not a run of the full default setup command or its PR-mining stage.

Each solver has its own history-free single-commit snapshot without a remote. Baseline gets no memory. Thinker gets the current orient output (750 estimated-token budget, two-note limit), plus optional thinker_lookup CLI access to its own mutable copy. This measures initial and on-demand cache retrieval, not native agent MCP transport or background maintenance. No cache is shared between solver arms or tasks. Source note hashes are frozen and checked afterwards. Source definitions may describe a current limitation; learning is intentionally pre-fix.

Coding configuration is identical within model pairs except memory/tool availability. Arm order alternates by task and model index. One active session per model, up to three models concurrently; wall times may reflect contention and provider caching, which is not reset. Agent prompts prohibit history, networking, installs, sibling files, hidden evaluator tests and delegation. OS sandbox strength differs by CLI; audit native tool inputs. No claims of hermetic read isolation.

Correctness uses unchanged upstream post-fix test modules copied into separate scoring worktrees after freezing solver patches. Before calls, all three base snapshots fail target cases and all gold patches pass; one Windows-only capture test is skipped on macOS. Acceptance and affected-module regression tests are separate, not a whole-repository test claim. Agent test changes cannot weaken the evaluator. No model judge is used.

Report coding input/output/cache-read/total tokens, tool calls and wall time separately by model and arm; report exploration, note preparation and retrieval costs separately. Missing usage stays unknown, failed runs remain failures with provider validity indicated. Efficiency ratios are meaningful alongside correctness, especially on pairs where both arms pass. Three tasks per model and one sample per arm are a canary, not a general performance claim. The older regression-recall failure-counting amendment does not alter this protocol.

Before coding, a harness schema adapter was corrected: note bodies returned as arrays of lines are joined with newlines. Original model responses are retained unchanged, no model call is repeated, and the same normalization applies to all cohorts. Failed preparation attempts and their Jev usage are retained.

Before any coding runs, cache construction was corrected to follow the actual session-learning path: parseTranscript → refineLearningPlan → distillEvents → prepareNotes → saveNotes. The initial source-definition-only prototype omitted relevant session evidence and rejected its broad agent-authored notes; those unscored preparation attempts are archived separately. Each of the nine fresh learning transcripts is now distilled once by its same high-effort model, adding nine setup calls. No learning session is rerun. Empty caches produced by this real pipeline remain an observed outcome and are included in the coding canary, with coverage reported explicitly. An experiment-only adapter pins all frontier distillation calls to high effort and records provider responses; it is not a product change.

Opus distillation initially reported a CLI failure (two internal failed calls are preserved in local usage). An explicit same-model resume was allowed without rerunning any valid result or changing prompts/effort. A failed Jev fetch interrupted the first resume before frontier inference; a subsequent resume reached the frontier call. The adapter was extended to retain failed raw CLI output; missing counters remain unknown. There were three failed frontier calls in total, not three valid draws from which a result was selected.

The captured Opus failure was subsequently identified as invalid structured output (missing required tags), not a model-identity change. Its failed setup is recorded explicitly; it contributes no notes and is not replaced with a different model or hand-written memory. Other completed cache-building outcomes are preserved. Coding continues with the cache actually produced, including empty or failed setup, so the canary can report correctness and diagnostic costs; an empty-cache cohort cannot establish a cache efficiency benefit.
