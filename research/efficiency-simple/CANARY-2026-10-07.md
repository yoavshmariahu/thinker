# Click canary: the cache reaches the agent, and costs it more

Author: Claude Fable 5.1 with Yoav. 2026-10-07. Thinker main `90161e3` plus the
uncommitted model-pins adapter (`research/performance-canary/model-pins.patch`).

Three Click tasks (`research/performance-canary/tasks.json`), two cohorts, both arms
of every task the cache covered. Cohorts: `claude-opus-5-5` through Claude Code and
`gpt-6.1-sol` through Codex, both at high effort for mining, phrasing, verification
and coding. One cache per cohort at the anchor commit (the oldest task's base), mined
from 60 commits of the task's past by `mine-prs --git`, described by `phrase`,
then copied per task and topped up with the commits merged before that task's base,
re-checked, re-verified and re-described. Grade: the upstream acceptance test, which
fails at every base and passes on every upstream fix.

Correctness is equal in every pair. With the cache the agent used more input tokens in
four of four pairs and more tool calls in four of four; wall time rose in three. The
Sol agents also called `find` or `drilldown` three times each. Input tokens include
provider cache reads. Noise between identical no-cache runs of one task, measured
earlier the same day, was about 12% of tokens and 25% of wall time, so the token
deltas are outside it and the single wall-time gain is not.

## The cache reached the agent

Before any coding run, each cohort's cache was probed with the exact coding prompt,
and a live run asked the agent to repeat back the titles of the notes it received:
Opus echoed both of its two, Sol echoed its one. Inside the coding runs, each cache
arm's `orient` row carries Jev scores and no cross-encoder fallback: Opus
0.52/0.48/0.45 and 0.66/0.63/0.50, Sol 0.77/0.45/0.26 and 0.75/0.53/0.42. The two
notes served for click-3391 are about CliRunner stream ownership and its
`should_strip_ansi` patching, for a task about CliRunner capture modes.

## What this canary found before it measured anything

The runs above are the fourth attempt. Each earlier attempt failed on a measurement
fault that would have read as a result, all recorded in the PRs of the day:
a sandbox HOME that logged the agent CLIs out (#121); the constraints preamble
retrieving in place of the task (#121); a daily token cap that failed 16 of 60 mined
changes and later refused every description (#124, #126); a summary gate at 0.9 that
kept 0 of 38 descriptions (#122, #123, #125); `--ignore-rules` suppressing Codex's
hooks (#130); and, found by this run, Codex starting the MCP server without the
parent's environment, so the server migrated the checkout's usage log into the
machine's and the runner read every Sol cache arm as a baseline. The Sol servings in
the table were recovered from the migrated log, scoped to each run's Codex thread;
the wiring now carries the environment and the runner refuses a migrated log.

## Reproduce

```sh
export THINKER_TEST=1 THINKER_BENCH_SOURCE=<click clone> THINKER_CODEX_AUTH=<codex auth.json>
python3 research/efficiency-simple/run.py build opus && python3 research/efficiency-simple/run.py build sol
python3 research/efficiency-simple/run.py probe opus && python3 research/efficiency-simple/run.py probe sol
python3 research/efficiency-simple/run.py solve opus && python3 research/efficiency-simple/run.py solve sol
python3 research/efficiency-simple/run.py score opus && python3 research/efficiency-simple/run.py score sol
```

Needs the model-pins adapter applied, logged-in `claude` and `codex`, a personal Jev
key, and `.venv-perf` built from `research/performance-canary/python-requirements.txt`
on Python 3.13. Run output is under `bench/runs/efficiency-simple/`, ignored by git.
