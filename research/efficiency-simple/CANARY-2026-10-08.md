# Click rerun: tasks that reopen a remembered fix, three seeds, both cohorts

Author: Claude Fable 5.1 with Yoav. 2026-10-08. Thinker `ca0ea76` on branch
`agent/rerun-fix-overlap` (main `f9db4a8` plus PR #133 and the offline-learning change
below), with the uncommitted model-pins adapter (`research/performance-canary/model-pins.patch`).

The morning's canary (`CANARY-2026-10-07.md`) served true notes that bore on none of its
tasks. This run chose tasks the cache has something to say about: of the six post-anchor
Click pull requests whose changed definitions carry notes of the morning's caches
(`tasks-fix-overlap.json`), the four the probe covered in both cohorts
(`tasks-fix-overlap-run.json`). Two of them, click-3482 and click-3533, are successive
fixes of the same issue (#3449, a pager closing a borrowed stdout), on code the cache holds
a rule about from an earlier fix (#3139: `_NamedTextIOWrapper` must never close its
buffer). Same cohorts as the morning, Opus 5.5 through Claude Code and GPT-6.1 Sol
through Codex at high effort, the same anchor caches (49 and 44 notes, mined from 60
commits before click-3364's base) topped up per task, and three seeds per arm. Grade:
the upstream acceptance test, which fails at every base and passes on every upstream fix.

## What the agents did with the notes

The notes were on target this time. For click-3482 and click-3533 both caches served the
stream-ownership rule at prompt time (Jev 0.62 to 0.86); for click-3484 the ParameterSource
rules; for click-3363 the flag-default rules (0.66 to 0.78). The edit hook added rules on the
definitions being changed, and, until the change described under "Edit hook" below, rules on
other definitions of the same hub file.

Opus (`shape` of each run from its events): the first edit comes at the same call in both
arms (4.0 against 4.3, 3.7 against 3.7, 4.7 against 4.7, 4.7 against 5.0), with the same
number of reads before it. The notes did not shorten the way to the code. What the thinker
arm does more of is run the tests: 6.3 pytest runs a run against 4.0 on click-3363, 4.7
against 3.0 on click-3484, 3.7 against 2.0 on click-3482. The rules mined from fixes name
their regression tests, and the agent runs them. Opus called no MCP tool in 24 runs.

Sol: the thinker arm calls `find` and `drilldown` 3.7 to 5 times a run, and its first edit
comes three calls later than the baseline's (10 against 7), after more reads, not fewer
(9 against 6). The tools were added to the agent's own exploration, not substituted for it.
Test runs are equal.

Decomposed for click-3363 on Opus (three seeds each): 13 against 17 API calls, 19.6k
against 21.2k context on the first call, 29.8k against 33.2k per call on average, 61s
against 70s of API time inside 70s against 88s of wall. Three quarters of the extra 155k
tokens are the four extra calls at full context; a quarter is the fatter context.

## The measurement fault the gate caught

The first attempt at this run was stopped after its first task. Every Opus thinker arm (6
of 6) ended with `ToolSearch` and a `remember` call, two turns the baseline could not spend,
although the workflow block told the agent learning was disabled: the MCP server's own
instructions still ended with the learning guide, and the server registered the learning
tools whatever `THINKER_NO_LEARN` said. With those turns the click-3363 Opus thinker arm
cost 699k; without them, 552k. Decided the same hour, at the user's direction: no guidance
asks an agent to save or grade notes, learning is the background distillation and never a
step on the critical path, and with learning off the server registers neither `remember` nor
`feedback` (commit `ca0ea76`). The contaminated records were deleted and the thinker arms
rerun; the finished baselines were kept. In the morning's run the same instructions had cost
nothing by chance.

## What was measured alongside

**A request-complexity gate does not separate.** One Jev judgment per request, on the 54
labelled tasks of three repositories and the nine Click tasks, asking whether carrying the
request out needs repository knowledge beyond what it says and what grep finds: AUC 0.60
against "an important note exists". A gate at 0.5 withholds 16 of 63 requests, 8 of which
had an important note; on Click it withholds click-3363 and click-3482 (0.42, 0.43), where
the cache serves a rule on the fix's own lines, and serves click-3391 and click-3364 (0.65,
0.55), where nothing useful existed. Whether a task needs the cache is a property of the
code and its history, not of how the request reads.

**The fixed cost per request, by part** (`tools/list` and `initialize` of the MCP server,
the workflow block, the hook's log): tool schemas about 1,050 tokens for the four retrieval
tools and 1,900 with `remember` and `feedback` (640 for `remember` alone), MCP instructions
275, workflow block 200, prompt-time bundle and intro about 490; edit-hook notes 400 to 850
an edit. Measured first-call difference between the arms: 1.6k.

## Changes made on this evidence

- **Edit hook** (`ops.js:lateNotes`): serves only rules whose dependency on the edited file
  changed between HEAD and the working tree, hashed as the cache hashes it; never a note
  about code on an edit of its test alone. In these runs an edit of flag types brought a rule
  about help-option caching and an edit of the test module a rule about choice options.
- **Learning tools opt-in** (`mcp.js`): `remember` and `feedback` are registered only with
  `mcp: { learningTools: true }` in the config. Nothing asks for them, Opus never called
  them, and their schemas cost about 850 tokens on every request.
- **Harness** (`run.py`): a task file (`THINKER_EFF_TASKS`), a pinned anchor checked to
  precede every base (`THINKER_EFF_ANCHOR`), seeds (`THINKER_EFF_SEEDS`), one topped-up
  cache per task and cohort shared by its seeds, edit-hook servings counted as coverage, API
  time beside wall time, one preflight per task set (two cohorts started together raced on
  the preflight checkouts and one lost a git lock), the probe run on the topped-up cache
  (probed on the anchor cache, click-3533 scored 0.52; its topped-up cache scored 0.41 to
  0.45 in the run and served nothing at prompt time), and the interpreter, import root and
  pytest plugins as parameters for a second repository.

## What this does not settle

The cache arm costs more on every Click pair even when its notes rest on the fix's own
lines and nothing distracts the agent. The remembered-fix hypothesis found no saving here:
both arms passed, and the baseline did not need the reminder on these tasks. Two readings
remain open, and the Click runs cannot tell them apart: that on tasks whose entry point one
grep finds there is nothing for a cache to save, so Click is the wrong repository to show a
gain; or that serving notes to a coding agent costs turns however relevant they are. The
next measurement is on another repository, with the changes above in place.

## Reproduce

```sh
export THINKER_TEST=1 THINKER_BENCH_SOURCE=<click clone> THINKER_CODEX_AUTH=<codex auth.json>
export THINKER_EFF_TASKS=research/efficiency-simple/tasks-fix-overlap-run.json
export THINKER_EFF_ANCHOR=8a2b48901a08b3d2ec3a9bbd151948a9765368c6 THINKER_EFF_SEEDS=3
python3 research/efficiency-simple/run.py build opus && python3 research/efficiency-simple/run.py build sol
python3 research/efficiency-simple/run.py probe opus && python3 research/efficiency-simple/run.py probe sol
python3 research/efficiency-simple/run.py solve opus & python3 research/efficiency-simple/run.py solve sol & wait
python3 research/efficiency-simple/run.py score opus && python3 research/efficiency-simple/run.py score sol
```

The anchor caches of 2026-10-07 were reused as built. Run output is under
`bench/runs/efficiency-simple/`, ignored by git.
